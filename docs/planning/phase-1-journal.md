# Phase 1 — Wins & Friction Journal

**Purpose:** committed log of distilled observations from real Phase 1 use — workflow wins worth preserving into Phase 2, and friction points that should shape Phase 2 design (or kill an assumption). The Phase 1 deliverable is a decision document (ship / iterate / abandon); this file is the evidence that decision will be made from.

**Relationship to other journals:**
- `vault/notes/_meta/Friction Journal.md` (gitignored) — raw, in-the-moment capture during daily use ("I wish it could…"). Personal, unfiltered.
- This file — distilled, committed observations. Periodically pull signal up from the vault friction journal; record wins observed in real use that aren't captured there.

**How to use:** date-stamp entries as `### YYYY-MM-DD — Short title`. Keep entries terse; the goal is signal density, not narrative.

## Wins

### 2026-04-27 — Audio Bible + mobile dictation as zero-friction capture

While listening to the audio Bible during commute, dictated quick notes directly into the Obsidian mobile app for later refinement. Capture-during-listening was effectively frictionless — no context switch, no app-switching, no typing while distracted. This is exactly the "behavior change is the goal" outcome PROJECT.md targets: the vault didn't pull the user away from audio, it absorbed audio into the note-taking loop.

**Signal for Phase 2:** the iOS app's note-capture surface needs to be at least as low-friction as Obsidian mobile's voice dictation. If the app makes capture *harder* than what's already working, it's a regression.

## Open questions surfaced during use

### 2026-04-27 — Unfinished daily readings — split or back-reference?

If a daily reading isn't completed in one calendar day (or the notes portion isn't finished), do we split the reading across multiple daily files or keep it in one? Current working answer: keep one file per *logical* reading (the plan day), filename = the date you started; if it spills, keep editing the same file. Skipped calendar days simply have no daily note. Tradeoff: the Calendar plugin's "this day has a note" indicator becomes incomplete on continuation days. Resolved-for-now by creating a stub on the continuation day pointing back at the original — re-evaluate if this becomes a recurring pattern.
